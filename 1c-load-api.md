# API 1С — полная загрузка данных

Документ описывает **6 веб-сервисов 1С**, которые используются нашими Go-сервисами для **полной загрузки** мастер-данных и документов в PostgreSQL MES Kitchen.

> ⚠️ Это **загрузка снимка** на дату — отдельный сценарий от Kafka-публикаций, где 1С присылает только изменения. Контракты Kafka — в `schemas/1c-api/`.

---

## Подключение

| Параметр | Значение |
|---|---|
| **Base URL** | `http://10.1.233.60/astor_test_anatoliy/hs/mes-kitchen` |
| **Метод** | `GET` для всех endpoint-ов |
| **Авторизация** | Basic Auth |
| **Логин** | `MESKitchenUser` |
| **Пароль** | `249636821` (тест) |
| **Content-Type ответа** | `application/json; charset=utf-8` |
| **Кодировка** | UTF-8 (имена на русском возвращаются как есть) |

**Пример curl:**
```bash
curl -u MESKitchenUser:249636821 \
  "http://10.1.233.60/astor_test_anatoliy/hs/mes-kitchen/base_units"
```

---

## Соглашения

| Артефакт 1С | Значение «пусто» | В нашей БД |
|---|---|---|
| GUID-поле | `"00000000-0000-0000-0000-000000000000"` | `NULL` |
| Дата | `"0001-01-01T00:00:00"` | `NULL` |
| Бессрочный срок действия | `date_of_expiring = "0001-01-01T00:00:00"` | `NULL` |

**Формат даты в параметрах запроса и ответах:** ISO 8601 без часового пояса — `YYYY-MM-DDTHH:MM:SS` (например, `2026-04-30T00:00:00`).

**Все идентификаторы — UUID v4** (lowercase, через дефис, например `698d5f11-f0d3-11ed-bb99-78ac4482b644`).

## 1. `GET /org-units`

Дерево структурных единиц (фабрики, кухни, торговые точки, склады). Источник в 1С: `Catalog_СтруктурныеЕдиницы`.

### Параметры

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `active` | `string` | Нет | `true` — вернуть только активные. Без параметра — все включая помеченные на удаление |

### Пример запроса

```
GET /org-units?active=true
```

### Пример ответа

```json
{
  "org_units": [
    {
      "ref_key": "3fb6d0f5-f01a-11ed-bb99-78ac4482b644",
      "code": 1,
      "name": "Центральный офис",
      "type": "Центральный офис",
      "parent_key": "00000000-0000-0000-0000-000000000000",
      "is_active": true
    },
    {
      "ref_key": "51290979-66fa-11f0-bba4-6cfe540ca391",
      "code": 502,
      "name": "ФК Алматы",
      "type": "Фабрика-кухня",
      "parent_key": "3fb6d0f5-f01a-11ed-bb99-78ac4482b644",
      "is_active": true
    },
    {
      "ref_key": "698d6053-f0d3-11ed-bb99-78ac4482b644",
      "code": 9,
      "name": "ALA РЦ01",
      "type": "Торговая точка",
      "parent_key": "3fb6d0f5-f01a-11ed-bb99-78ac4482b644",
      "is_active": true
    }
  ],
  "total": 521
}
```

### Поля ответа

**Корневой объект:**

| Поле | Тип | Описание |
|---|---|---|
| `org_units` | `array` | Массив структурных единиц |
| `total` | `integer` | Общее количество записей в ответе |

**Элемент `org_units[]`:**

| Поле | Тип | Описание |
|---|---|---|
| `ref_key` | `uuid` | Уникальный идентификатор СЕ |
| `code` | `integer` | Числовой код СЕ (например, 502 = ФК Алматы) |
| `name` | `string` | Наименование |
| `type` | `string` | Тип: `Фабрика-кухня`, `Торговая точка`, `Цех`, `Центральный офис` и др. |
| `parent_key` | `uuid` | GUID родителя (для построения дерева). `00000000-...` = корень иерархии |
| `is_active` | `boolean` | Используется ли СЕ (если `false` — фабрика закрыта, точка перестала работать и т.п.) |

### Особенности

- **Дерево строится через `parent_key`** — он ссылается на `ref_key` записи этого же справочника.
- В нашей БД (`org_units.parent_id`) пустой GUID превращается в `NULL`.

## 4. `GET /nomenclature`

Номенклатура (товары/блюда), для которой есть **активная** технологическая карта в указанной СЕ на указанную дату. Источник в 1С: `Catalog_Номенклатура` отфильтрованный через `Document_ТехнологическаяКарта`.

### Параметры

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `id_ce` | `uuid` | ✅ | GUID структурной единицы (например, `51290979-66fa-11f0-bba4-6cfe540ca391` = ФК Алматы) |
| `date` | `string` (ISO 8601) | ✅ | Дата, на которую ищутся активные ТК. Формат `YYYY-MM-DDTHH:MM:SS`. Для получения всей номенклатуры (без фильтра по сроку) — `0001-01-01T00:00:00` |

### Пример запроса

```
GET /nomenclature?id_ce=51290979-66fa-11f0-bba4-6cfe540ca391&date=2026-04-30T00:00:00
```

### Пример ответа

```json
{
  "items": [
    {
      "guid": "ddd7ff16-f347-11ed-bb9a-6cfe540ca391",
      "name": "Круасан с мясом",
      "code": "00001234",
      "unit": "698d5f11-f0d3-11ed-bb99-78ac4482b644"
    },
    {
      "guid": "e9c797ef-f347-11ed-bb9a-6cfe540ca391",
      "name": "Тесто слоёное",
      "code": "00005678",
      "unit": "698d5f18-f0d3-11ed-bb99-78ac4482b644"
    }
  ]
}
```

### Поля ответа

**Корневой объект:**

| Поле | Тип | Описание |
|---|---|---|
| `items` | `array` | Массив номенклатурных позиций |

**Элемент `items[]`:**

| Поле | Тип | Описание |
|---|---|---|
| `guid` | `uuid` | Уникальный идентификатор номенклатуры |
| `name` | `string` | Наименование товара/блюда |
| `code` | `string` | Внутренний код в 1С |
| `unit` | `uuid` | GUID **базовой** единицы измерения → `base_units.guid` |

### Особенности

- В ответ попадает **только та номенклатура**, у которой есть техкарта с `date_of_expiring >= date` (или бессрочная) и привязка к указанной `id_ce`.
- Это означает: справочник сужается под конкретную дату и фабрику. Сырьё «вообще» не приходит — только то, что используется в рецептурах.

## 5. `GET /tech_cards2`

Технологические карты (рецептуры) — шапка + состав ингредиентов + список СЕ/цехов, в которых ТК действует. Источник в 1С: `Document_ТехнологическаяКарта` с табличными частями `Состав` и `СтруктурныеЕдиницы`.

> ⏱️ Самый **долгий** endpoint в API. Возвращает ~13к ТК для ФК Алматы за ~80-100 секунд из-за объёма данных. Клиенту нужен таймаут ≥ 180 секунд.

### Параметры

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `id_ce` | `uuid` | ✅ | GUID структурной единицы |
| `date` | `string` (ISO 8601) | ✅ | Дата, на которую ищутся активные ТК. Для получения всех — `0001-01-01T00:00:00` |

### Пример запроса

```
GET /tech_cards2?id_ce=51290979-66fa-11f0-bba4-6cfe540ca391&date=2026-04-30T00:00:00
```

### Пример ответа

```json
{
  "items": [
    {
      "guid": "fc394e06-a561-4cea-8003-8c2be3a8d4c3",
      "number": "1-00003344",
      "date": "2026-03-05T13:09:39",
      "date_of_expiring": "0001-01-01T00:00:00",
      "quantity": 1,
      "id_nomenclature": "ddd7ff16-f347-11ed-bb9a-6cfe540ca391",
      "description": "Круасан с мясом, выход 100 г",
      "content": [
        {
          "id_nomenclature": "e9c797ef-f347-11ed-bb9a-6cfe540ca391",
          "quantity": 1.943,
          "unit": "698d5f18-f0d3-11ed-bb99-78ac4482b644"
        },
        {
          "id_nomenclature": "0079d508-2ef1-11ef-bba3-6cfe540ca391",
          "quantity": 0.05,
          "unit": "698d5f18-f0d3-11ed-bb99-78ac4482b644"
        }
      ],
      "СЕ": [
        {
          "id_се": "51290979-66fa-11f0-bba4-6cfe540ca391",
          "id_workshop": "0228f6b4-34ac-11f1-9dcb-40a6b71f5b21"
        }
      ]
    }
  ]
}
```

### Поля ответа

**Корневой объект:**

| Поле | Тип | Описание |
|---|---|---|
| `items` | `array` | Массив технологических карт |

**Шапка ТК (элемент `items[]`):**

| Поле | Тип | Описание |
|---|---|---|
| `guid` | `uuid` | Уникальный идентификатор техкарты |
| `number` | `string` | Номер документа в 1С |
| `date` | `string` (ISO 8601) | Дата создания/редакции карты |
| `date_of_expiring` | `string` (ISO 8601) | Дата окончания действия. `0001-01-01T00:00:00` = бессрочно |
| `quantity` | `number` | Количество порций/выхода продукции по карте |
| `id_nomenclature` | `uuid` | Что производим — продукция → `nomenclature.guid` |
| `description` | `string` | Текстовое описание/комментарий к карте |
| `content` | `array` | Состав — список ингредиентов (см. ниже) |
| `СЕ` | `array` | Список СЕ/цехов, где действует карта (см. ниже) |

**Табличная часть `content` (состав/ингредиенты):**

| Поле | Тип | Описание |
|---|---|---|
| `id_nomenclature` | `uuid` | Ингредиент → `nomenclature.guid` |
| `quantity` | `number` | Количество ингредиента (в указанной единице) |
| `unit` | `uuid` | Единица измерения ингредиента → `base_units.guid` |

**Табличная часть `СЕ` (структурные единицы и цеха):**

| Поле | Тип | Описание |
|---|---|---|
| `id_се` | `uuid` | Структурная единица → `org_units.ref_key` |
| `id_workshop` | `uuid` | Цех производства → `workshops.guid`. `00000000-...` = карта привязана только к СЕ, без конкретного цеха |

### Особенности

- **Кириллица в названии поля `СЕ`** — это сделано на стороне 1С, у нас в Go-моделях используется `json:"СЕ"` тег.
- **Дубли в `СЕ`-таблице возможны** — 1С может прислать две строки с одинаковыми `id_се` и разным `id_workshop` или наоборот. На приёме у нас (`mes-sync`, `tech-cards-loader`) применяется дедупликация по `(id_се, id_workshop)`.
- Поля **могут быть пустыми**: пустые GUID-ы (`00000000-...`), пустая дата (`0001-01-01...`), пустые строки.
- 1С возвращает **все ТК для СЕ**, фильтр по дате применяется на 1С-стороне через `date_of_expiring >= :date OR date_of_expiring = 0001-01-01`.

## 6. `GET /goods-orders2`

Заказы магазинов на доставку готовой продукции с фабрики. Источник в 1С: `Document_ЗаказТоваров` с табличной частью.

### Параметры

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `id_ce` | `uuid` | ✅ | GUID фабрики (СЕ-производитель) |
| `date` | `string` (ISO 8601) | ✅ | Дата отгрузки (`date_of_shipment`). Один день — например, `2026-04-30T00:00:00`. Для всех — `0001-01-01T00:00:00` |

### Пример запроса

```
GET /goods-orders2?id_ce=51290979-66fa-11f0-bba4-6cfe540ca391&date=2026-04-30T00:00:00
```

### Пример ответа

```json
{
  "items": [
    {
      "guid": "a1b2c3d4-1111-2222-3333-444455556666",
      "number": "ЗТ-00012345",
      "date": "2026-04-29T18:30:00",
      "date_of_shipment": "2026-04-30T06:00:00",
      "ce_id": "51290979-66fa-11f0-bba4-6cfe540ca391",
      "shop_id": "698d6053-f0d3-11ed-bb99-78ac4482b644",
      "content": [
        {
          "parent_id": "a1b2c3d4-1111-2222-3333-444455556666",
          "nomenclature_id": "ddd7ff16-f347-11ed-bb9a-6cfe540ca391",
          "unit_id": "698d5f11-f0d3-11ed-bb99-78ac4482b644",
          "quantity": 50.0
        },
        {
          "parent_id": "a1b2c3d4-1111-2222-3333-444455556666",
          "nomenclature_id": "e9c797ef-f347-11ed-bb9a-6cfe540ca391",
          "unit_id": "698d5f18-f0d3-11ed-bb99-78ac4482b644",
          "quantity": 12.5
        }
      ]
    }
  ]
}
```

### Поля ответа

**Корневой объект:**

| Поле | Тип | Описание |
|---|---|---|
| `items` | `array` | Массив заказов магазинов |

**Шапка заказа (элемент `items[]`):**

| Поле | Тип | Описание |
|---|---|---|
| `guid` | `uuid` | Уникальный идентификатор заказа |
| `number` | `string` | Номер документа в 1С |
| `date` | `string` (ISO 8601) | Дата создания документа |
| `date_of_shipment` | `string` (ISO 8601) | Дата отгрузки заказа (по ней работает фильтр запроса) |
| `ce_id` | `uuid` | Фабрика-производитель → `org_units.ref_key` |
| `shop_id` | `uuid` | Магазин-получатель → `org_units.ref_key` |
| `content` | `array` | Позиции заказа (см. ниже) |

**Табличная часть `content` (позиции заказа):**

| Поле | Тип | Описание |
|---|---|---|
| `parent_id` | `uuid` | GUID шапки заказа (дублирует `items[].guid`). На приёме мы это поле игнорируем — у нас есть контекст родителя из обхода |
| `nomenclature_id` | `uuid` | Заказанная номенклатура → `nomenclature.guid` |
| `unit_id` | `uuid` | Единица измерения → `base_units.guid` |
| `quantity` | `number` | Заказанное количество |

### Особенности

- **Фильтр по `date_of_shipment`** — не по дате создания, а по дате когда товар должен быть отгружен. Логично для планирования производства.
- За один день `0001-01-01` (= «все») может вернуться очень много данных — реальная история заказов магазинов за всё время. Клиент должен учитывать таймаут.

              ┌──────────────────┐   │
              │ /goods-orders2   │───┘
              │ .ce_id           │ ─────► /org-units.ref_key
              │ .shop_id         │ ─────► /org-units.ref_key
              │ .content[].nom_id│ ─────► /nomenclature.guid
              └──────────────────┘

## Порядок загрузки

При первичной загрузке (пустая БД) выдерживается порядок ради foreign-key целостности:

1. `/org-units` — корень всех ссылок (СЕ — самостоятельный объект)
2. `/workshops` — ссылается на org-units
3. `/base_units` — самостоятельный
4. `/nomenclature` — ссылается на base_units
5. `/tech_cards2` — ссылается на nomenclature + base_units + org_units + workshops
6. `/goods-orders2` — ссылается на org_units + nomenclature + base_units

После шага 5 локально выполняется `workshop_mapping` (UPDATE в `tech_card_org_units.workshop_id` из JSON-файла; в 1С не ходит).

## Ошибки

1С обычно возвращает:

| HTTP | Когда |
|---|---|
| `200 OK` | Успех — JSON-тело со списком |
| `401 Unauthorized` | Неверный Basic Auth |
| `404 Not Found` | Неправильный путь endpoint-а или СЕ не существует |
| `500 Internal Server Error` | Ошибка на стороне 1С (например, проблема с БД 1С) |

В случае 500 тело ответа — текст с описанием ошибки, не JSON.

## Связь с Kafka

Параллельно полной загрузке через эти endpoint-ы, 1С **публикует точечные изменения** в Kafka-топики `mes.*.changed.v1` (см. `schemas/1c-api/`). Это **дополнение**, а не замена:

- **Endpoint-ы** — для bootstrap-а БД и периодической полной перезаливки
- **Kafka-события** — для актуализации между перезаливками (real-time дельта)

Подробнее — в `MEMORY.md` (раздел про mes-sync) и `Project.md` (описание сервиса mes-sync).
